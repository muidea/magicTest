## 4. 功能测试场景

### 场景 N1: 命名空间作用域逻辑
- **前置条件**: 无
- **测试步骤**:
  1. 创建全局治理 scope (`"*"` ) 命名空间
  2. 创建显式治理范围 (`"manager;child:*"`) 命名空间
  3. 创建未显式传入 scope 的命名空间
  4. 验证治理边界和默认回填逻辑
- **预期结果**: `Namespace.Scope` 作为治理范围被正确处理

### 场景 N2: 命名空间时间管理
- **前置条件**: 当前时间戳
- **测试步骤**:
  1. 创建有效时间范围的命名空间
  2. 创建已过期的命名空间
  3. 创建未开始的命名空间
  4. 验证时间相关的业务逻辑
- **预期结果**: 时间管理功能正常

### 场景 N3: 超级 Namespace 管理边界
- **前置条件**: 超级 namespace scope 已纳入目标 namespace
- **测试步骤**:
  1. 创建 manager namespace 和 target namespace
  2. 在 manager scope 中纳入 target
  3. 验证 manager 可更新/删除 target
  4. 验证 scope 外 namespace 越权失败
- **预期结果**: namespace 管理边界按 `Namespace.Scope` 工作

## 5. 测试优先级

1. **P0 (高优先级)**: N-TC-001, N-TC-002, N-TC-011, N-TC-015 (基础功能)
2. **P1 (中优先级)**: N-TC-003, N-TC-008, N-TC-009, N-TC-010, N-TC-012, N-TC-013 (常用功能)
3. **P2 (低优先级)**: 所有异常和边界测试用例

## 6. 特殊注意事项

- **作用域逻辑**: 命名空间的作用域字段影响其他实体的访问权限
- **时间管理**: 命名空间的时间范围影响实体在该命名空间内的有效性
- **治理范围**: namespace `scope` 表示管理边界，不再解释为层级关系字段
- **全局作用域**: `"*"` 表示全局治理权限，需要特殊处理
